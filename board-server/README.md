# CCGA Private Board Portal

A small, dependency-free Node server that runs the **private** board area. The
public website stays on GitHub Pages; this owns everything that must be
board-only. It authenticates a board member with a one-time email link against
a roster and serves confidential pages **only to an active session** — nothing
private is ever in a file a browser can fetch without signing in.

## Why this exists

A password typed onto the static site is public: that page is served to anyone
with the URL. Real "board-only" needs a server that checks who you are before
it sends the data. That is this.

## How it works

- **Magic-link sign-in.** Enter your email; if it's on the roster you get a
  one-time link (24h, single-use). No passwords.
- **Server-side sessions.** The cookie is `<id>.<HMAC(id)>`, `HttpOnly`,
  `Secure`, `SameSite=Lax`. A forged cookie is rejected before the database is
  touched. Because the login page *and* the private pages are served from this
  one origin, the cookie has no cross-site problem.
- **Closed roster.** No self-registration. Only an `is_active` member can sign in.
- **Storage:** one SQLite file (`node:sqlite`, no native build). On Render it
  lives on a persistent disk so it survives restarts.

## Deploy to Render

1. **New + → Blueprint**, point it at this repo. Render reads `board-server/render.yaml`.
   (Or: New + → Web Service, root directory `board-server`, build `npm install`,
   start `node --experimental-sqlite server.js`, add a 1 GB disk at `/data`.)
2. It needs a **paid instance** (Starter) because the SQLite file requires a
   persistent disk. `DB_PATH` is set to `/data/board.db`.
3. After the first deploy, set these in the dashboard (Environment):
   - `PUBLIC_ORIGIN` — the service's `https://…onrender.com` URL (later, your
     `board.cologrowers.com`). Links are built from this, so it must be right.
   - `RESEND_API_KEY` — from resend.com, so links can be emailed.
   - `MAIL_FROM` — a verified Resend sender, e.g. `CCGA Board <board@cologrowers.com>`.
   - `BOOTSTRAP_ADMIN_EMAIL` / `BOOTSTRAP_ADMIN_NAME` — on a fresh (empty) DB,
     this one admin is seeded on boot so you can sign in and take it from there.
   - `SESSION_SECRET` is generated by Render automatically.
4. Open the URL, enter the bootstrap admin email, click the emailed link.

## Seed the roster

```
# locally, or as a Render one-off job
node --experimental-sqlite scripts/seed.js roster.json
```

`roster.json` (gitignored — it has real emails):
```json
[{ "email": "you@cologrowers.com", "full_name": "Your Name", "role": "President", "is_admin": true }]
```

## Run locally

```
cp .env.example .env          # leave RESEND_API_KEY empty to log links to the console
node --experimental-sqlite scripts/seed.js roster.example.json
COOKIE_SECURE=false npm start # COOKIE_SECURE=false only for http on localhost
npm test                      # auth unit tests
```

## What goes in the portal

`src/pages.js` → `portalPage()` renders the private area. Confidential board
material (NCGA access notes, documents, the things that must not be public)
lives here, behind the session — not on the public site. Add sections there as
needed.

## Notes

- Nothing secret is committed: `.env`, `data/`, `*.db` and `roster.json` are
  gitignored. The committed source is safe to be public; the data is not in it.
- Moving off the Cloudflare Worker: this replaces the Worker's role for the
  board area. The public site is untouched.
